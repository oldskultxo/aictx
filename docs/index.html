What AICTX does

AICTX helps a new coding-agent session start from the useful state left by the previous one. Instead of rediscovering the repository, the agent can resume from repo-local evidence: active task state, next action, known failures, decisions, execution summaries and optional structural repo hints.

Continuity runtime

A small resume/finalize loop lets coding agents load useful context before work and record factual evidence after work.

Repo-local context

AICTX stores inspectable continuity artifacts inside the repository, not as hidden cloud memory or a private black box.

Agent-aware workflow

Codex-first, Claude-aware, GitHub Copilot-aware and compatible with generic agents that can read repo instructions and run CLI commands.

Why AICTX?

Most coding-agent sessions still start cold. The agent reopens broad docs, rediscovers repository structure, repeats failed commands and depends on chat history to understand unfinished work.

Without AICTX

Session 1 does the work, the chat ends, and Session 2 starts by rediscovering the repo, repeating context gathering and risking the same mistakes again.

With AICTX

Session 1 records continuity, and Session 2 resumes from a compact capsule with the active task, next action, known failures, decisions and relevant repo context.

Result

The next coding-agent session can start closer to the intended work surface instead of spending its first minutes recovering project state.

Operational memory for AI coding agents

AICTX is not just a prompt. It is a repo-local memory layer focused on operational continuity: what happened, what failed, what was decided, what should happen next and where the agent should look first.

Work State

Preserves active task, hypothesis, files, next action, risks and verification state so the next session knows what was in progress.

Decision memory

Keeps explicit architecture, product and implementation decisions available to future coding-agent sessions.

Failure memory

Stores observed command, test, build and lint failures as evidence so agents do not blindly repeat known mistakes.

Handoff memory

Captures factual summaries and next steps that let a later session continue from the right surface.

Execution memory

Records what happened during execution and makes continuity visible instead of depending only on chat history.

RepoMap hints

Optional structural repo lookup can provide compact entry points for where the agent should inspect first.

Supported coding agents

AICTX is runner-aware, not runner-locked. It is designed for coding agents that can read repository instructions, run CLI commands and consume structured JSON output.

Codex

Codex-first workflow with repo instructions and a CLI/runtime contract built around resume and finalize.

GitHub Copilot

Repository-wide custom instructions through .github/copilot-instructions.md.

Claude

Claude-aware setup through project instructions and workspace-oriented guidance.

Generic agents

Any agent that can read repo instructions, run shell commands and consume JSON can use the AICTX runtime loop.
